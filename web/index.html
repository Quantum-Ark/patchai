THE PROBLEM

Generated code is not verified code.

Current AI coding assistants generate syntax based on probability, not verification. In production software, blind patches create hidden liabilities.

01

Plausible patches fail tests.

A generated code snippet can read convincingly, parse cleanly, and still fail basic unit assertions because the model hallucinated an internal API signature or variable scope.

41% of unverified LLM patches fail initial baseline execution.
02

Fixes introduce silent regressions.

A patch that solves the reported bug frequently destroys edge-case logic elsewhere in the codebase. Without automated full-suite regression checks, broken code gets merged.

Case #3 proved naive volume clamp broke existing VIP pricing tiers.
03

Agents report success without verification.

Most agentic workflows mark tasks "Complete" merely because the LLM generated an output message. PatchPilot refuses completion without tamper-evident command execution proof.

Zero PRs promoted without dual-suite passing exit code 0.
WORKFLOW

The 6-stage evidence pipeline.

PatchPilot replaces uncontrolled LLM loops with a structured deterministic execution flow. Every stage is bounded by timeout budgets and rollback handlers.

01

Inspect the issue

Parses the issue specification, analyzes candidate source files, and maps the abstract syntax tree in a clean worktree.

Tool: RepositoryTool · Entire Graph AST map
02

Reproduce the failure

Executes a targeted reproduction test in an isolated subprocess. Confirms the defect reproduces genuinely with an exit code != 0 before touching any code.

Requirement: Non-zero exit code confirmation
03

Plan and apply a patch

Synthesizes a minimal surgical replacement snippet via configured LLM provider (OpenAI, Anthropic, Gemini). Validates path boundaries and mirrors in-memory backups.

Protection: Path traversal prevention · Memory backup store
04

Execute tests

Runs acceptance tests first. If passed, automatically triggers the complete repository regression test suite in an isolated sandbox.

Subprocess budget: 60s timeout · Scrubbed secret env
05

Recover from failure

If tests fail or regressions occur, PatchPilot triggers an atomic rollback to baseline. It classifies the failure category, updates hypothesis, and replans Attempt #2.

Budget: Max 3 recovery attempts · RetryPolicy classifier
06

Verify the result

Requires 100% test pass confirmation across acceptance and regression suites. Exports Neatlogs telemetry trace ID and creates an audited draft PR.

Outcome: State labeled VERIFIED with command hashes

BOUNDARIES & INTEGRITY

Trust, guarantees, and limitations.

We believe developer tools must be honest about their boundaries. Here is what PatchPilot verifies and what it cannot guarantee.

What PatchPilot Verifies

  • Baseline defect confirmation: Proves the bug exists by executing reproduction commands before editing code.
  • Regression immunity: Evaluates existing unit suites to confirm no previous behavior was broken.
  • Clean workspace state: Zero uncommitted debris left in your repository when a test attempt fails.
  • Command-level proof: Exports exact exit codes, stdout, stderr, and run durations into audit reports.

Current Boundaries & Limitations

  • Test suite reliance: If a codebase lacks sufficient regression tests, PatchPilot cannot verify unexercised paths.
  • Human-in-the-loop required: PatchPilot drafts pull requests. It never automatically merges or deploys code.
  • Sandbox scope: Uses subprocess timeouts (60s) and path validation. Full hypervisor or container isolation is planned.
  • Model constraints: Complex distributed race conditions across multiple services require human architectural guidance.
