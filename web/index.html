THE PROBLEM

A generated patch is only a hypothesis.

Current AI coding assistants generate code based on syntax probability, not execution proof. Without automated testing and rollback, generated code introduces silent liabilities.

UNVERIFIED HYPOTHESIS

Plausible Code Without Proof

A generated patch can look clean to human eyes, pass syntax validation, and still destroy edge-case logic elsewhere in your codebase.

Naive Clamp Proposal (Attempt #1) FAILED REGRESSION

THE REPAIR CURRENT PIPELINE

Seven stages of verifiable repair.

A persistent deterministic pipeline. Every stage is bounded by timeout budgets, subprocess isolation, and automated rollback handlers.

01 / STAGE

Inspect

Parses issue specification, resolves candidate source files, and maps abstract syntax trees in a disposable worktree.

Tool: Entire Graph AST map
02 / STAGE

Reproduce

Executes targeted reproduction test in isolated subprocess. Proves baseline failure exit code != 0 before editing code.

Gate: Non-zero exit code confirmation
03 / STAGE

Diagnose

Analyzes stack traces and candidate snippets. Classifies error pattern (SyntaxError, LogicError, BoundaryError).

Module: Failure Classifier
04 / STAGE

Patch

Synthesizes minimal surgical replacement diff via configured LLM provider. Validates path traversal boundaries.

Tool: PatchTool (Memory Mirror)
05 / STAGE

Test

Executes acceptance tests first, then triggers the entire test suite in an isolated subprocess with scrubbed secrets.

Subprocess: 60s timeout budget
06 / RECOVERY

Recover

On test regression, auto-restores clean baseline SHA, injects error traceback into context, and pivots strategy.

Budget: Max 3 recovery cycles
07 / VERIFY

Verify

Requires 100% exit code 0 across acceptance and regression suites. Exports Neatlogs trace and drafts unmerged PR.

Outcome: State labeled VERIFIED

SYSTEM DESIGN

High-level architecture.

A modular pipeline separating LLM hypothesis generation from deterministic test execution and filesystem rollback.

STEP 1

Issue Intake

Parses GitHub issue URL or markdown spec. Resolves candidate files and stack trace lines.

→
STEP 2

Disposable Sandbox

Isolated ephemeral git worktree. Target files guarded against symlink and path traversal attacks.

→
STEP 3

Baseline Reproduction

Executes targeted reproduction command. Verifies baseline exit code != 0 in isolated subprocess.

→
STEP 4

Failure-Driven Recovery

Detects regressions, triggers atomic rollback, and replans strategy using real failure tracebacks.

→
STEP 5

Independent Verification

Dual test suites must exit with code 0. Generates audit report and publishes trace to Neatlogs.
